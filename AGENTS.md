## Команда агентов проекта

Перед изменениями прочитай GitHub Issue, проверь назначенных исполнителей и связанные открытые PR, включая Draft. Следуй [порядку начала работы и сдачи](.codex/project-team/WORKFLOW.md), [профилю проекта](.codex/project-team/PROJECT.md) и [матрице проверок](.codex/project-team/QUALITY.md).

**Один Issue — отдельная ветка и отдельный PR.** Не объединяй реализацию нескольких Issues в одной ветке или PR. При обнаружении такого PR проверяющий агент сразу закрывает его без слияния и ожидания ревью, оставляет причину и просит разделить изменения по Issues. Подробности — в [регламенте](.codex/project-team/WORKFLOW.md#один-issue--одна-ветка-и-один-pr).

Роли постоянных команд описаны в [TEAMS.md](.codex/project-team/TEAMS.md). Без записи в локальном реестре можно выполнить Issue по поручению своего пользователя в роли исполнителя. Полномочия CEO и оркестратора определяются назначением.

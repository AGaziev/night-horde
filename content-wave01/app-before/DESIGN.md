# Ночная орда — дизайн и протокол

Кооперативный онлайн «выживач»: до 8 игроков в комнате, автоатакующее оружие, орда врагов,
кристаллы опыта, выбор 1 из 3 улучшений без паузы, боссы на 5:00 и 10:00, победа — продержаться 15:00.
Все числа и тексты контента — в `public/shared/content.js` (общий для сервера и клиента, ESM).

## Структура

```
package.json            "type": "module", dependency "ws", start: node server/server.js
server/server.js        HTTP (static + API), WebSocket /ws, SSE /api/events, POST /api/send, сессии
server/game.js          Room + симуляция (без сетевого кода): class Room { addPlayer, removePlayer, handle(pid,msg), tick(dt) }, отправка через колбэк send(pid,msg)/broadcast
public/index.html       одна страница, <link rel="icon" href="/_gw/icon">
public/style.css
public/js/*.js          ESM-модули клиента (net.js, game.js, render.js, ui.js, input.js, main.js)
public/shared/content.js
```

Без сборки, без внешних CDN. Сервер слушает `process.env.PORT || 3000`, отдаёт `public/` по `/`.

## Платформа (важно)

- Приложение открывается за шлюзом Вайбкода. Шлюз передаёт имя пользователя в заголовке
  `x-vibe-user-name-encoded` (decodeURIComponent) и id в `x-vibe-user-id`. Нет заголовков — локальный запуск: имя «Игрок N».
- Неизвестно, пропускает ли туннель WebSocket. Поэтому два транспорта с одинаковыми сообщениями:
  1. WebSocket `wss://<host>/ws?sid=<sid>` — каждое сообщение JSON-текст.
  2. Запасной: SSE `GET /api/events?sid=<sid>` (поток `data: <json>\n\n`, заголовки сразу, `X-Accel-Buffering: no`,
     `Cache-Control: no-cache`, heartbeat-комментарий `: hb\n\n` каждые 10 с) + `POST /api/send?sid=<sid>` с телом-JSON
     (одно сообщение или массив сообщений), ответ `204` сразу.
- Клиент сначала пробует WS; если `open` не пришёл за 3 с или соединение закрылось до первого сообщения — переключается на SSE+POST
  и запоминает выбор до перезагрузки страницы. При обрыве — переподключение тем же sid (сервер держит игрока 20 с).
- Один sid — одно активное соединение; новое соединение с тем же sid вытесняет старое.

## Сессия

`GET /api/session` → `{ sid, name }`. sid — случайная строка, привязывается к игроку (pid = числовой id внутри сервера).
Клиент хранит sid в sessionStorage, чтобы переподключение после обрыва вернуло его в ту же комнату.
`GET /health` → `200 ok`.

## Сообщения клиент → сервер

| t | поля | смысл |
|---|------|-------|
| `name` | `name` (≤20 симв.) | сменить имя |
| `list` | — | запросить список комнат |
| `create` | `hero` | создать комнату и войти хостом |
| `join` | `code`, `hero` | войти в комнату (только в состоянии lobby; в идущую игру — нельзя, ответ err) |
| `leave` | — | выйти из комнаты |
| `hero` | `hero` | выбрать героя в лобби |
| `ready` | `v` (bool) | готовность |
| `start` | — | хост запускает игру (можно и без готовности всех) |
| `pos` | `x`, `y`, `fx`, `fy` | позиция своего героя (клиент считает движение сам, 15 Гц) и направление взгляда (единичный вектор) |
| `pick` | `i` (0..2) | выбор улучшения из текущего предложения |
| `again` | — | хост после конца игры возвращает комнату в лобби |
| `ping` | `c` | замер задержки |

## Сообщения сервер → клиент

| t | поля |
|---|------|
| `welcome` | `pid`, `name`, `room` (код или null — при переподключении) |
| `rooms` | `rooms: [{code, host, players, state}]` — только комнаты в lobby |
| `lobby` | `code`, `host` (pid), `players: [{pid, name, hero, ready, color}]` |
| `start` | `players: [{pid, name, hero, color, x, y}]` — игра началась, время 0 |
| `s` | снимок (ниже), 10 Гц всем в комнате |
| `lvl` | `choices: [{id, kind: 'weapon'|'passive', name, icon, desc, level}]`, `pending` (сколько ещё выборов в очереди) — адресно игроку. `level` — уровень ПОСЛЕ выбора. Если улучшать нечего — `choices: [{id:'heal', kind:'heal', name:'Лечение', icon:'✚', desc:'+30 здоровья', level:0}]` |
| `over` | `win` (bool), `time`, `stats: [{pid, name, hero, kills, dmg, level}]` |
| `err` | `msg` (по-русски, для показа) |
| `pong` | `c` |

### Снимок `s`

```
{
  t: 's',
  tm: 123.4,               // игровое время, с
  k: 512,                  // убийств всего
  p: [[pid, x, y, hp, maxHp, level, xp, xpNext, st, rev, fx, fy, w]],
       // st: 0 жив, 1 упал; rev: прогресс подъёма 0..100; w: [[weaponId, level], ...]
  e: [id, type, x, y, hpPct, ...],     // плоский массив по 5; type — индекс в ENEMY_TYPES; целые
  b: [],                               // не используется: снаряды идут событиями shot/ptgt/pend
  g: [id, x, y, tier, ...],            // кристаллы, плоский по 4; tier 0 (≤2 xp), 1 (≤9), 2 (больше)
  z: [id, x, y, r, ...],               // лужи зелья, плоский по 4
  fx: [[kind, ...args]],               // события с прошлого снимка:
       // ['hit', x, y, dmg]          — цифра урона
       // ['die', x, y, type]          — смерть врага
       // ['zap', x1, y1, x2, y2]     — молния (x1,y1 — небо над целью или предыдущая цель цепи)
       // ['slash', pid, dir, range, width] — удар клинка; dir: 1 вправо, -1 влево
       // ['hurt', pid]               — игрок получил урон
       // ['down', pid] / ['up', pid] — упал / поднят
       // ['lvl', pid]                — игрок получил уровень
       // ['boss', name]              — появился босс
       // ['chest', x, y]             — с босса выпал сундук (всем по выбору улучшения)
       // ['shot', id, kind, x, y, vx, vy, life, targetId|-1, tm] — выстрел; клиент сам ведёт снаряд,
       //    искра наводится на врага targetId по той же формуле, что и сервер
       // ['ptgt', id, targetId|-1, tm] — снаряд сменил или потерял цель
       // ['pend', id, x, y, tm]      — снаряд исчез (попал или истёк)
       // ['slowz', puddleId]         — появилась лужа, замедляющая врагов (особенность Алхимика);
       //    клиент запоминает id и подкрашивает такую лужу и врагов в ней
       // Снаряды часто живут меньше интервала снимков, поэтому клиент разбирает эти события сразу при получении.
  boss: [hp, maxHp] | null
}
```

Позиции орбиты и радиус ореола клиент вычисляет сам: `orbitAngle(tm, rps, i, count)` и `radius * areaMul`
из content.js. Для этого клиенту нужны пассивы: в `p` они не идут, поэтому `areaMul` клиент может игнорировать
для чужих игроков, а для своего — считать по своим выборам. (Упрощение допустимо.)

## Правила симуляции (сервер)

- Тик 30 Гц фиксированным шагом 1/30 с; после короткой остановки цикла (до 0,25 с) сервер догоняет пропущенные тики,
  чтобы `tm` снимка шло вровень с настенными часами (по нему клиент строит часы отрисовки). Снимок каждые 3 тика. Позиция игрока — из последнего `pos`; сервер ограничивает скачок
  `speed * dt * 1.5 + 30` от прежней позиции и игнорирует `pos` упавших.
- Спавн: по `WAVES` и `spawnRateScale(players)`, кольцо `SPAWN_DISTANCE` вокруг случайного живого игрока.
  Лимит `MAX_ENEMIES`. Враги дальше 1400 от всех живых игроков переносятся на кольцо снова.
- Враг идёт к ближайшему живому игроку; простое расталкивание врагов (сетка/спатиальный хэш, без O(n²)).
  `wisp` двигается зигзагом. hp врага × `enemyHpScale`.
- Контакт: если враг касается игрока, игрок без i-frames получает `dmg` врага и i-frames `PLAYER_IFRAMES`.
- Смерть врага → кристалл с xp врага; если кристаллов больше `MAX_GEMS` — xp добавляется в ближайший.
- Сбор: в радиусе магнита кристалл летит к игроку `GEM_PULL_SPEED`, при касании — xp ему, и `GEM_SHARE` — остальным живым.
- Уровень: xp ≥ `xpForNext(level)` → level+1, в очередь игроку предложение из 3 случайных вариантов:
  новое оружие (если < MAX_WEAPONS), улучшение имеющегося (< MAX_LEVEL), новый/улучшенный пассив.
  Пока игрок не выбрал, следующее предложение ждёт в очереди. Игра не останавливается.
- Упал (hp ≤ 0) → st=1. Живой союзник в `REVIVE_RADIUS` копит прогресс; `REVIVE_SECONDS` → поднят с `REVIVE_HP_FRACTION`.
  Все упали → `over` с win=false. Время ≥ `RUN_SECONDS` → `over` win=true.
- Босс на `BOSS_TIMES`: hp × число игроков; смерть — сундук: каждому живому игроку дополнительное предложение улучшения.
- Выход игрока посреди игры: его герой удаляется. Пустая комната удаляется. Хост ушёл — хост следующий.
- Статистика: kills и dmg по игроку (кто нанёс смертельный удар / сколько урона).
- Особенности героев — данные `HEROES[id].trait` (параметры) и `traitDesc` (строка для карточки);
  сервер читает их через `heroTrait(id)` и не проверяет имя героя. Отсутствующие поля нейтральны (`NO_TRAIT`):
  - `auraHeal` (Звонарь, 1) — другие живые игроки внутри его Ореола (`radius * areaMul` текущего уровня) лечатся на N hp/с;
  - `dmgTaken` (Кузнец, 0.8) — множитель получаемого урона; `taunt` (Кузнец, 250) — враг, у которого живой
    такой герой ближе этого расстояния, идёт к нему, а не к ближайшему игроку;
  - `chainBonus` (Заклинательница бурь, 1) — добавочные перескоки молнии Грозы;
  - `puddleSlow` (Алхимик, 0.35) — враги внутри его луж движутся медленнее на эту долю, пока внутри (+0.1 с).
  Особенность действует на соответствующее оружие героя, даже если оно взято позже, а не стартовое.
- Внешний вид: `HEROES[id].orbitSkin = 'hammer'` — Хоровод рисуется молотами (только клиент).

## Клиент

- Экраны: меню (имя, список комнат с кнопкой «Войти», «Создать комнату», поле «Код комнаты»), лобби
  (код и кнопка «Скопировать ссылку» вида `<origin>/?room=CODE`, герои-карточки, игроки, «Готов», «Начать» у хоста),
  игра (canvas во весь экран), итоги (таблица, у хоста «Ещё раз», у всех «В меню»).
- Открытие по `?room=CODE` → сразу join.
- Движение: WASD/стрелки, на сенсорных экранах — виртуальный джойстик. Локальное предсказание своего героя
  (скорость из героя и пассива swift), отправка `pos` 15 Гц.
- Чужие игроки и враги — интерполяция между снимками с адаптивной задержкой. Часы отрисовки:
  `now − p90(приход − tm) − p90(интервал между tm) − 20 мс` по последним 40 снимкам (~4 с); к цели время отрисовки
  подтягивается плавно (скорость ±12%), прыжком — только при расхождении больше 0,5 с. Обычно задержка 150–250 мс.
  Если новый снимок опоздал, враги и чужие игроки до 0,2 с продолжают движение по скорости из двух последних снимков.
  Снимок с `tm` не больше предыдущего отбрасывается (кроме событий снарядов). Враг, сдвинувшийся между снимками
  больше чем на max(200, 400·Δtm) px, ставится сразу, без проезда через карту. Враг, которого не было в предыдущем снимке
  (вошёл в радиус отбора 1000 px), появляется на месте.
  Снаряды — интерполяция по id, новые появляются, пропавшие исчезают.
- Камера за своим героем; фон — тёмная земля с процедурной плиткой/травой (детерминированно по координате тайла).
- Всё рисуется кодом на canvas (без картинок): враги — разные силуэты/цвета из content.js, у героя — цвет игрока и имя.
- HUD: таймер, убийства, полоса опыта, уровень, здоровье, иконки оружия с уровнями, полоса здоровья босса,
  мини-список союзников со здоровьем, индикатор транспорта (WS/SSE) и пинг.
- Выбор улучшения — панель с 3 карточками поверх игры, клавиши 1/2/3 или клик; игра продолжается.
- Упавший союзник — силуэт и круг прогресса подъёма; стрелка на краю экрана к упавшим союзникам.
- Эффекты: цифры урона, вспышки смерти, молнии, дуга клинка, тряска экрана при получении урона.
- Язык интерфейса — русский. Оформление — тёмная игровая тема.

# Ночная орда — дизайн и протокол

Кооперативный онлайн «выживач»: до 8 игроков в комнате, автоатакующее оружие, орда врагов,
кристаллы опыта, выбор 1 из 3 улучшений без паузы, боссы на 5:00 и 10:00, победа — продержаться 15:00.
Все числа и тексты контента — в `public/shared/content.js` (общий для сервера и клиента, ESM).

## Структура

```
package.json            "type": "module", dependency "ws", start: node server/server.js
server/server.js        HTTP (static + API), WebSocket /ws, SSE /api/events, POST /api/send, сессии
server/game.js          Room + симуляция (без сетевого кода): class Room { addPlayer, removePlayer, handle(pid,msg), tick(dt) }, отправка через колбэк send(pid,msg)/broadcast
server/snapshot-codec.js  кодер снимков (дельты, протокол 11); public/js/snapshot-codec.js — общие таблицы и декодер
public/index.html       одна страница, <link rel="icon" href="/_gw/icon">
public/style.css
public/js/*.js          ESM-модули клиента (net.js, game.js, render.js, ui.js, input.js, main.js)
public/shared/content.js
```

Без сборки, без внешних CDN. Сервер слушает `process.env.PORT || 3000`, отдаёт `public/` по `/`.

## Платформа (важно)

- Приложение открывается за шлюзом Вайбкода. Шлюз передаёт имя пользователя в заголовке
  `x-vibe-user-name-encoded` (decodeURIComponent) и id в `x-vibe-user-id`. Нет заголовков — локальный запуск: имя «Игрок N».
- Неизвестно, пропускает ли туннель WebSocket. Поэтому два транспорта с одинаковыми сообщениями:
  1. WebSocket `wss://<host>/ws?sid=<sid>&v=<протокол>` — каждое сообщение JSON-текст.
  2. Запасной: SSE `GET /api/events?sid=<sid>&v=<протокол>` (поток `data: <json>\n\n`, заголовки сразу, `X-Accel-Buffering: no`,
     `Cache-Control: no-cache`, heartbeat-комментарий `: hb\n\n` каждые 10 с) + `POST /api/send?sid=<sid>` с телом-JSON
     (одно сообщение или массив сообщений), ответ `204` сразу.
- Клиент сначала пробует WS; если `open` не пришёл за 3 с или соединение закрылось до первого сообщения — переключается на SSE+POST
  и запоминает выбор до перезагрузки страницы. При обрыве — переподключение тем же sid (сервер держит игрока 20 с).
- Один sid — одно активное соединение; новое соединение с тем же sid вытесняет старое.

## Сессия

Лог забега (v8, `server/runlog.js`): `GET /api/runs` → `{ runs: [{id, at, v, win, time, players: [{name, hero, level}]}] }`
(последние 30 в памяти), `GET /api/runs/<ID>` → JSON лога, `GET /api/runs/<ID>.txt` → сводка + JSON (то же, что копирует
кнопка «Скопировать лог»). Копия на диске — `HORDE_RUNS_DIR` (по умолчанию `/tmp/horde-runs/<ID>.json`, до 200 файлов,
при старте последние 30 подгружаются). В логе: версия, исход, по минутам (`enemies, hpMul, dmgMul, alive, lvl[], taken,
downs, kills, dps, load%`), по игроку — выборы `[время, уровень, pick|skip|reroll, id, kind, level, предложенные]`,
связки/эволюции с временем, урон по источникам, полученный урон по врагам, падения/подъёмы, мин. здоровье, сборка.
Персональных данных нет: только имя в игре. `bosses: [{type, name, at, hp, killedAt, sec, downs: {имя: n}, downsByBoss}]`.

Боссы (v8): 3:00, 6:00, 9:00, 12:00 — Матерь роя, Рогач, Костяной органист, Двуликий в случайном порядке без
повторов (`BOSS_POOL`), 14:30 — Владыка ночи (`FINAL_BOSS`). HP = `def.hp × bossHpScale(t, игроки)`. Типы дописаны в
конец `ENEMY_TYPES`: `brood, ram, gunner, twin, twinhalf`. Атаки телеграфируются ≥ 0,6 с: `warn` (круг), `bline`
(полоса), бит `ST.windup` (свечение замаха). Сундук — когда умерла вся группа босса (обе половины Двуликого).

`GET /api/session` → `{ sid, name }`. sid — случайная строка, привязывается к игроку (pid = числовой id внутри сервера).
Клиент хранит sid в sessionStorage, чтобы переподключение после обрыва вернуло его в ту же комнату.
`GET /health` → `200 ok`.

| `err` | `msg` (по-русски, для показа) |
| `pong` | `c` |

### Снимок `s`

Так выглядит снимок после декодирования (`SnapshotDecoder` в `public/js/snapshot-codec.js`); на проводе он
упакован — см. «Формат снимка на проводе» ниже.

```
{
  t: 's',
  tm: 123.4,               // игровое время, с
  k: 512,                  // убийств всего
  p: [[pid, x, y, hp, maxHp, level, xp, xpNext, st, rev, fx, fy, w, ward]],   // ward — заряды Оберега/Бастиона
       // st: 0 жив, 1 упал; rev: прогресс подъёма 0..100; w: [[weaponId, level], ...];
       // у Хоровода и Мельницы при Эхо третье поле — добавочные клинки: ['orbit', level, extra];
       // связка — ['duoId', 1..3]; Планетарий — ['orrery', level, extra, readyMask] (искры на орбите битами)
  e: [id, type, x, y, hpPct, st, ...], // плоский массив по 6; type — индекс в ENEMY_TYPES; целые;
       // st — биты состояния (ST в content.js): 1 горение, 2 холод, 4 заморозка, 8 сырость, 16 метка,
       // 32 корни, 64 элита, 128 щит (Щитоносец, протокол 16), 256 замах/фитиль (Плевун и Трубач целятся, у Пузыря горит фитиль);
       // при бите 128 биты 9–12 — направление щита: (st >> SHIELD_SHIFT) & 15 из SHIELD_DIRS = 16 (0 — вправо, по часовой)
  b: [],                               // не используется: снаряды идут событиями shot/ptgt/pend
  g: [id, x, y, tier, ...],            // кристаллы, плоский по 4; tier 0 (≤2 xp), 1 (≤9), 2 (больше), 3 золотой
  z: [id, x, y, r, ...],               // лужи зелья, плоский по 4
  tr: [id, x, y, kind, pid, ...],      // капканы, плоский по 5; kind 0 капкан, 1 мина, 2 мина перезаряжается, 3 шип
  syn: 8,                              // «Слаженность» отряда, %
  it: [id, type, x, y, ...],           // предметы на земле, плоский по 4; type — индекс в ITEM_TYPES
  fx: [[kind, ...args]],               // события с прошлого снимка:
       // ['hit', x, y, dmg]          — цифра урона; крит: ['hit', x, y, dmg, 1, pid]
       // ['die', x, y, type]          — смерть врага
       // ['zap', x1, y1, x2, y2]     — молния (x1,y1 — небо над целью или предыдущая цель цепи)
       // ['slash', pid, dir, range, width] — удар клинка; dir: 1 вправо, -1 влево
       // ['hurt', pid]               — игрок получил урон
       // ['down', pid] / ['up', pid] — упал / поднят
       // ['lvl', pid]                — игрок получил уровень
       // ['boss', name]              — появился босс
       // ['bline', x1, y1, x2, y2, w, life] — полоса-телеграф рывка босса (v8)
       // ['chest', x, y]             — с босса выпал сундук (всем по выбору улучшения)
       // ['shot', id, kind, x, y, vx, vy, life, targetId|-1, tm] — выстрел; клиент сам ведёт снаряд,
       //    искра наводится на врага targetId по той же формуле, что и сервер
       // ['ptgt', id, targetId|-1, tm] — снаряд сменил или потерял цель
       // ['pend', id, x, y, tm]      — снаряд исчез (попал или истёк)
       // ['slowz', puddleId]         — появилась лужа, замедляющая врагов (особенность Алхимика);
       //    клиент запоминает id и обводит такую лужу (холод на врагах — бит 2 в `e`)
       //    у серпа в shot ещё два поля: [..., tm, ownerPid, outT] — летит прямо outT секунд, затем прямо к владельцу
       // ['eshot', id, x, y, vx, vy, life, tm] / ['epend', id, tm] — вражеский снаряд (летит прямо)
       // ['lob', id, x0, y0, x1, y1, fuse, tm, kind] — бросок (kind 0 петарда, 1 Коктейль, 2 Ледяная граната);
       // ['boom', x, y, r, kind] — взрыв (0 петарда, 1 Пузырь, 2 вспыльчивая элита, 3 Шаровая молния,
       //    4 Ледяная граната, 5 мина, 6 Коктейль)
       // ['tslash', pid, range, width, big] — удар Громового разреза (big — каждый 3-й, с веером);
       //    ['tfan', pid, r] — кольцо молний веера; молнии-громоотводы и веер приходят обычными 'zap'
       // ['orb', id, x0, y0, x1, y1, speed, life, tm, r] — Шаровая молния: летит прямо к точке, висит до конца life
       // ['zk', puddleId, look] — вид лужи: 1 горящая (Коктейль), 2 облако (Кадило)
       // ['shard', x, y] — осколки Ледяной гранаты; ['duo', pid, duoId] — игрок собрал связку
       // ['evo', pid, evoId] — эволюция; ['cone', pid, angle×100, range, halfAngleDeg] — свет Фонаря;
       // ['crescent', pid, r] — удар Полумесяца; ['bell', pid, r] — волна Набата; ['ward', pid, charges] — заряды щита
       // lob kind 3 — Салют; boom kind 7 — вспышка Оберега, 8 — Салют; tr kind 4 — Волчья яма
       // Ледяной след диска сервер в снимок не шлёт: клиент рисует его по траектории диска (shot kind 3)
       // ['warn', x, y, r, delay]    — круг будущего взрыва (Пузырь убит, элита «Вспыльчивый»)
       // ['frost', pid, r]           — волна Инея от героя
       // ['snap', x, y]              — сработал капкан
       // ['brk', tx, ty]             — разбит объект в тайле (tx, ty) (координаты — breakableAt в content.js)
       // ['item', pid, type, x, y]   — игрок подобрал предмет; ['open', pid, x, y] — открыт малый сундук
       // ['elite', enemyId, affix]   — враг стал элитой (affix — индекс в ELITE_AFFIXES)
       // ['blink', x, y]             — элита «Призрачный» мигнула отсюда
       // ['inv', pid, r]             — нашествие: кольцо врагов радиуса r вокруг игрока
       // ['react', kind, x, y, r]   — реакция состояний (волна 2); kind — индекс в REACTION_IDS (content.js):
       //    0 Проводник (r — лужа), 1 Вспышка, 2 Раскол, 3 Пар (r — облако на REACT.steamLife с), 4 Подрыв, 5 Наледь;
       //    сервер шлёт не больше 10 за снимок, подпись над местом клиент показывает не чаще раза в 0,5 с на вид
       // ['banner', pid, x, y, life, r] — Знамя воткнуто: союзникам в r +20% урона и +10% скорости на life с
       //    (скорость считает клиент сам, пока стоит в круге; у владельца одно знамя — новое заменяет старое)
       // Маяк (beacon) и Огненное колесо (firewheel) событий не шлют: клиент рисует их по w и времени снимка
       //    (beaconAngle и orbitAngle в content.js); Залп и Фаланга — обычные shot копий (kind 4) и ножей
       // Снаряды часто живут меньше интервала снимков, поэтому клиент разбирает эти события (shot, ptgt, pend,
       // eshot, epend, lob, brk, elite) сразу при получении.
  boss: [hp, maxHp, type] | null   // type — индекс ENEMY_TYPES; у раздвоившегося Двуликого — сумма половин
  ev: [index, left, phase, x, y, r, a, b]  // активное событие волны 4 (протокол 16), только пока оно идёт; index — в EVENTS:
       // star: phase 0 — метка (r — круг удара, left — до удара), 1 — осколок лежит в (x, y);
       // gold: (x, y) — Золотая тень; fog: круг тумана; altar: a — индекс в ALTAR_DEALS;
       // cursed: phase 0 — сундук ждёт, 1 — волна (r — кольцо, left — сколько держаться); streak: a/b — убито/цель
}

```

### Формат снимка на проводе (протокол 11)

Код: `server/snapshot-codec.js` (кодер, один на комнату), `public/js/snapshot-codec.js` (общие таблицы и декодер),
тест — `node server/codec-test.js`. Без сжатия: обычный JSON-текст, одинаково идёт по WS и SSE.

- Версия протокола — `PROTO` в `public/js/snapshot-codec.js`. Клиент передаёт её в `?v=` при подключении, сервер — в
  `welcome.v`. Клиент, увидев другую версию, один раз перезагружает страницу (не чаще раза в минуту). Подключение без
  `v` (вкладка, открытая до обновления) получает обычные снимки как раньше и сообщение `err` «Игра обновилась — обновите
  страницу (F5)».
- Каждый снимок имеет номер `sq` (1, 2, … с начала забега). Ключевой (`K: 1`) самодостаточен; остальные — дельта к снимку
  `sq − 1`. Ключевой уходит всем каждые `KEY_EVERY` = 10 снимков (раз в секунду), при `start`/`resync` (переподключение)
  и адресно тому, кто прислал `kf`. Клиент, получивший дельту не к своему последнему снимку (потеря, сброс буфера
  сервера), не применяет её, отправляет `kf` (не чаще раза в 300 мс) и до ключевого берёт из снимков только события `fx`.
- Поля `tm`, `k`, `syn`, `boss`, `b` и любые новые поля верхнего уровня идут как есть.
- Строчные каналы `p`, `e`, `g`, `z`, `tr`, `it` (таблица `CHANNELS`: где в строке x и y; ширина строки — `SNAP_STRIDE`
  в `server/game.js`, для `p` — длина строки). Запись канала:
  - `{ r, w, n }` — значение целиком (первый снимок, сменилась ширина строки, канал не раскладывается на строки);
  - `{ w, m?, c?, a?, v? }` — изменения относительно строк предыдущего снимка в их порядке; нет записи в дельте — канал не
    изменился. В ключевом снимке все строки идут в `a`.
  - `m` — по символу на строку предыдущего снимка: `.` без изменений, `*<n>` n строк подряд без изменений, `!` строка
    исчезла, два символа алфавита — сдвиг x и y на −32…31, `~` — x и y в `c`. Хвост без изменений опускается.
  - `c` — токены `[номер строки, маска полей, значения отмеченных полей…]` (бит f — поле f строки; поле 0 — id не меняется).
  - `a` — новые строки целиком, в конец списка. Порядок строк — порядок появления, а не порядок массивов сервера.
- События: `f` — строка токенов `[имя, число аргументов, аргументы…]`; имя — номер в `FX_NAMES` (с 1); имена не из
  таблицы — в `fn` (номер `FX_NAMES.length + 1 + индекс`); `0` — событие целиком из `fv`.
- Токены: целое — zigzag, база 32, алфавит `0-9A-Za-z-_` (символы 0–31 — продолжение, 32–63 — последняя цифра);
  `!<целое>` — число в тысячных; `^<целое>` — тысячные относительно `tm` (время событий); `~` — следующее значение из
  массива `v`/`fv` (строки, массивы, прочие числа). Кодирование без потерь: после декодирования значения совпадают с
  исходными.
- Новое поле в строке врага (или другого канала): дописать в push в `Room.snapshot()` и поправить `SNAP_STRIDE` —
  кодек переносит любые поля. Новое событие `fx` работает без правок кодека (через `fn`); частое лучше дописать в
  конец `FX_NAMES`.

Трафик (8 игроков, 350 врагов, поздняя игра, `perf-lab/bytes11.mjs`): ~32 КБ/с на клиента против 134 КБ/с
у JSON-снимков; ключевой снимок ~8 КБ, дельта ~2,6 КБ.

Позиции орбиты и радиус ореола клиент вычисляет сам: `orbitAngle(tm, rps, i, count)` и `radius * areaMul`
из content.js. Для этого клиенту нужны пассивы: в `p` они не идут, поэтому `areaMul` клиент может игнорировать
для чужих игроков, а для своего — считать по своим выборам. (Упрощение допустимо.)

## Правила симуляции (сервер)

### Режимы, пауза, открытие героев (v14)

- Режим комнаты (`MODES` в content.js): «Полная ночь» 15:00 и «Обед» 10:00. Комната живёт по «ночному времени» `Room.nt = time × 900 / runLength`:
  по нему идут `WAVES`, давление (hp/урон врагов), боссовый hp, размер вторжений и элиты. Интервалы элит и вторжений делятся на тот же
  множитель. Боссы — `bossTimes(runLength)`: в «Обеде» 2:00, 4:00, 6:00, 8:00, финальный 9:30; пики по долям длины, «Рассвет» с
  сгоранием в конце. Опыт кристаллов ×`MODES[mode].xpMul` (1,5), hp врагов в группе ×`hpMul` (соло ×1, группа ×1,13 — `modeHpMul`).
- Копейщица (`spearmaiden`, 150 hp, скорость 150, стартовое Копьё): «Таран» — её копья (и копья Залпа, Фаланги, Знамени) отбрасывают
  вдвое дальше и бьют на 12% сильнее за каждого уже пронзённого врага (`trait.spearRam`, `trait.spearKb`).
- Пауза только в соло: меню паузы (Esc, ⏸, уход вкладки в фон) и открытый выбор улучшения останавливают тик целиком (время, спавн,
  кулдауны, `pos` игнорируется). При переходе в паузу сервер досылает последний снимок, после неё клиент заново привязывает часы.
- Открытие героев: стартово Страж, Ведьма, Алхимик; остальные — `UNLOCKS` (победа → Заклинательница бурь, 5:00 Стражем → Кузнец,
  10 подъёмов союзников → Звонарь, 600 убийств ножами и их связками/эволюцией → Следопыт, 5 убитых боссов → Копейщица). `?unlockall=1` открывает всех (запоминается, `?unlockall=0` — выключить).

### Редкость карточек (v13)
- Каждая карточка оружия или артефакта при выдаче получает редкость: веса 70/22/7/1 (`RARITIES`), удача героя
  (Клевер `fortune` + Подкова `luck`) умножает вес редкости i на (1 + удача × i). Связки, эволюции, угли, лечение и
  «Кузня удачи» без редкости.
- Артефакт: прибавка = perLevel × `PASSIVE_BASE` (0,75) × ×1/×1,5/×2,2/×3,5, округлённая до показа; накопленное значение —
  `h.pval[id]` (клиент повторяет в `game.pvals` для скорости и площади). Уровень артефакта по-прежнему +1 (слоты, эволюции).
- Оружие: +1/+1/+2/+2 уровня (не выше максимума), редкая и легендарная — ещё +1 «Перебросить».
- Сундук элиты — хотя бы одна редкая, сундук босса — хотя бы одна эпическая (`CHEST_FLOOR`); «Перебросить» сохраняет пол.
- Лог: в `picks` редкость взятой карточки (7-е поле), в списке выданных `*r`; `team[].rarity` и `rarity` — сколько выпало
  и взято каждой редкости; строка «Редкость карточек: …» в сводке.

- Тик 30 Гц фиксированным шагом 1/30 с; после короткой остановки цикла (до 0,25 с) сервер догоняет пропущенные тики,
  чтобы `tm` снимка шло вровень с настенными часами (по нему клиент строит часы отрисовки). Снимок каждые 3 тика. Позиция игрока — из последнего `pos`; сервер ограничивает скачок
  `speed * dt * 1.5 + 30` от прежней позиции и игнорирует `pos` упавших.
- Спавн: по `WAVES` и `spawnRateScale(players)` (= 0,3 + 0,7 × игроков: на одного игрока почти как в соло),
  кольцо `SPAWN_DISTANCE` вокруг случайного живого игрока.
- Давление (content.js, `PRESSURE`, `INVASION`): здоровье врагов `enemyHpScale` = +12%/мин, после 3:00 ещё квадратичный
  член, с 9:00 — второй квадратичный множитель финала (соло ×0,4, вдвоём ×0,85 к его силе), × (1 + 0,55 × (n − 1) + 0,05 × (n − 1)²), n — число игроков; урон врагов (контакт, сгустки,
  взрывы Пузыря) после 3:00 растёт на 6% в минуту (`enemyDmgScale`). С 3:30 раз в минуту «нашествие»: кольцо врагов
  текущей волны r = 430 вокруг каждого живого игрока (10 + 2 за минуту после 3:00, до 40; вдвоём ×0,75, в соло нашествий нет, у групп от 4 игроков с 6:00 ×1,25),
  событие `['inv', pid, r]`. Элиты после 10:00 — раз в 30 с.
  Лимит `MAX_ENEMIES`. Враги дальше 1400 от всех живых игроков переносятся на кольцо снова.
- Враг идёт к ближайшему живому игроку; простое расталкивание врагов (сетка/спатиальный хэш, без O(n²)).
  `wisp` двигается зигзагом. hp врага × `enemyHpScale`.
- Контакт: если враг касается игрока, игрок без i-frames получает `dmg` врага и i-frames `PLAYER_IFRAMES`.
- Смерть врага → кристалл с xp врага (с шансом `GOLD_GEM_CHANCE` × (1 + удача) — золотой, ×5 опыта).
  Кристаллы не уплывают (G1): при лимите `MAX_GEMS` (200) самый дальний от всех игроков кристалл сливается в новый
  (в точке смерти); раз в `GEM_SWEEP_EVERY` с кристаллы дальше 1400 px от всех живых сливаются в один
  в 450 px от ближайшего игрока в их сторону. Громила раз в 2 минуты роняет «Зов углей» — все кристаллы летят к подобравшему.
- Сбор: в радиусе магнита кристалл летит к игроку `GEM_PULL_SPEED`, при касании — полный xp каждому игроку отряда
  (упавшим тоже: поднятый союзник не отстаёт). Порог уровня `xpForNext(level, players)` умножен на
  `teamXpMul(n) = n / (1 + 0,3 (n − 1))`, поэтому темп уровней в группе как при прежней доле 30%, соло не меняется.
- Слоты: `MAX_WEAPONS` = 4 оружия и `MAX_PASSIVES` = 4 артефакта. Когда слоты заняты, новое не предлагается —
  только улучшения взятого, «Перебросить», «Отказаться». Карточка нового показывает, какой слот займёт; в HUD — «N/4».
- Эволюции (5.4): оружие 5 ур. + свой артефакт любого уровня → карточка `kind: 'evo'` в 1-м слоте (раньше связки),
  отказ откладывает на 2 предложения. Эволюция заменяет оружие (тот же слот, один уровень), артефакт остаётся;
  эволюционированное оружие не входит в связку, оружие в связке не эволюционирует. 11 эволюций (`EVOS`):
  Рой светляков, Полумесяц, Ливень лезвий, Жернова, Набат, Буревал, Лунный серп, Салют, Вьюга, Волчья яма, Бастион.
  Волна 2: Трясина (Зелье + Ледяное сердце), Маяк (Фонарь + Подкова), Огненная тропа (Пламенный след + Уголёк),
  Знамя (Копьё + Узы; Узы предлагаются только в комнате от 2 игроков).
- Состояния и реакции (волна 2, раздел 5.3 плана). Состояния — поля врага (`burnT/burnDps`, `slowT/slow`, `frozenT`,
  `wetT/wetZ`, `markT/markMul`, `rootT`) и биты `st` в снимке. Источники: сырость — лужи Зелья, Трясины, Коктейля,
  облака Кадила (`z.wet`); горение — След, Огненная тропа, Огненное колесо, Петарда (8% удара/с, 3 с), лужа Коктейля,
  Минное поле, Уголёк, первый удар Грозы при Угольке; холод — Иней, сияние, Вьюга, след диска, лужи Алхимика,
  Трясина, Ореол при Ледяном сердце (15%); заморозка — `Room.freeze` (общая для Инея 5 ур., гранаты, сияния, Вьюги,
  диска и Наледи, с иммунитетом 1,5 с); корни — `Room.root` (капканы, Волчья яма, шипы Растяжки; боссов не держат).
  Реакции — `Room.react` внутри `hurtEnemy` по тегам удара (`REACT` в content.js — числа):
  Проводник (сырость + shock: разряд 50% по всем в той же луже, раз в 0,5 с на лужу), Вспышка (горение + shock:
  взрыв r 50 на 10 + 30% удара, горение снимается), Раскол (заморозка + phys: ×2, оттаивает, осколки r 40 на 30%),
  Пар (горение + cold или холод + fire: оба снимаются, облако r 60 на 2 с, контактный урон врагов в нём −50%; раз в
  2 с на врага), Подрыв (корни + fire и aoe: ×1,25), Наледь (сырость + cold: заморозка 0,8 с × сила контроля),
  Свет (метка: ×(1 + markMul)), Озноб (холод + Ледяное сердце: + chillVuln). Урон от горения и побочный урон реакций
  (`src.react`) реакций не вызывает; побочный урон идёт в статистику как `r_<id>`, счётчики — в логе `reactions`.
- Прямые синергии оружие + артефакт (`SYNERGIES`): крит-нож пробивает ещё одного, удар Хоровода при Кольчуге копит
  −1 к следующему полученному удару (до 3), Ореол + Ледяное сердце холодит, Гроза + Уголёк поджигает первым ударом,
  Петарда + Эхо (+2) кладёт взрывы крестом через 50 px, корни Капканов × длительность (Песочные часы), Серп летит
  со скоростью героя, Копьё у союзника (≤ 60 px) при Узах +30%. Карточки показывают «💥 реакция … с …» и «✦ с …».
- «Угли» (`EMBERS`): когда улучшать нечего (или вариантов меньше трёх), вместо «Лечения» — постоянный бонус до конца
  забега: +5% урона, −4% перезарядки или +15 макс. здоровья (+30 здоровья); складываются.
- Оружие волны 3 без новых состояний: Фонарь (конус на самую плотную группу, метка +урон от всех), Пламенный след
  (горящие языки на пути, поджог), Копьё (в самого живучего: босс > элита > hp, пробивает, откидывает),
  Оберег (заряды поглощают удар целиком, вспышка при последнем; заряды — `p[13]`).
- Ограничения контроля: после заморозки враг 1,5 с не замерзает снова; откидывание не чаще раза в секунду на врага,
  элиты — вдвое слабее. Так «Мельница»/Хоровод + Иней не превращаются в стену.
- Связки оружия (раздел 5.8 плана): таблица `DUOS` в content.js, поиск по паре `DUO_BY_PAIR[duoKey(a, b)]`;
  пары взятого оружия проверяются в одном месте — `Room.updateCombos(h)` (`h.combos = [{id, a, b, ready}]`).
  16 связок: 13 из плана (с «Прожектором бури» — Гроза + Фонарь) и 3 волны 2 — Залп (Копьё + Ножи: копьё роняет
  ножи в стороны), Фаланга (Копьё + Оберег: стена копий, сломанный заряд — кольцо копий), Огненное колесо (Хоровод +
  Пламенный след: горящие колёса и огненный круг). Каждое оружие — в 1–3 связках. Условие — обе части ≥ 3 ур.; карточка
  `kind: 'duo'` в 1-м слоте; отказ или выбор другой карточки откладывает её на 2 предложения. Связка занимает слот
  первой части, слот второй освобождается; части больше не предлагаются. Уровни I–III (`DUO_MAX_LEVEL`), стартовый —
  по сумме частей (≤ 7 → I, 8–9 → II, 10 → III). Не больше `MAX_DUOS` = 2 у игрока. Артефакты действуют как на
  обычное оружие; урон связки несёт теги обеих частей. Особенности героев переходят на связку: Звонарь лечит
  Полярным сиянием, лужи Коктейля и Кадила замедляют у Алхимика, цепь Громового разреза +1 у Заклинательницы.
  Стартовое оружие героя тянет к своим связкам: новые оружия-партнёры в предложениях с весом ×2.
  «Слаженность»: +4% урона всей команде за каждую уникальную связку в отряде (до +20%), снимок `syn` (проценты).
  Капканы Растяжки не исчезают, а перезаряжаются (2,5 с), иначе сеть нитей рвётся в толпе.
- «Лечение» третьей карточкой приходит, только если в момент создания предложения здоровья меньше 35% (на карточке
  написано почему) или улучшать больше нечего.
- Уровень: xp ≥ `xpForNext(level)` → level+1, в очередь игроку предложение из 3 вариантов с весами (G4):
  1-й слот — улучшение уже взятого (оружия или артефакта), 2-й — 50/50 улучшение или новое, 3-й — любое;
  новое оружие — не больше одной карточки и не в двух предложениях подряд; при hp < 35% 3-й слот — «Лечение»;
  иначе 3-й слот с шансом 5% × (1 + удача) (из малого сундука 30%) — редкая «Кузня удачи».
  «Перебросить» (2 за забег, +1 за «Перо») и «Отказаться» (+10 опыта). Пока игрок не выбрал, следующее
  предложение ждёт в очереди. Игра не останавливается.
- Модификаторы героя `mods` (`baseMods()` в content.js) пересчитываются из артефактов; артефакт с полем `values`
  берёт значение по уровню, иначе `perLevel × уровень`. Сейчас действуют: `dmgMul`, `cdMul`, `speedMul`,
  `magnetMul`, `areaMul`, `regen`, `critChance`/`critMul` (Острота), `amount` (Эхо: +снаряды у Искры, Ножей,
  Серпа, Петарды, лужи Зелья, удары Грозы, клинки Хоровода), `durMul` (Песочные часы: лужи, холод, заморозка),
  `armor` (Кольчуга: урон = max(1, урон × dmgTaken − armor)); остальные поля нейтральны до волн 2–3.
- Единая точка урона `hurtEnemy(e, dmg, h, src)`, `src = { weapon, tags }` (теги оружия в `WEAPONS[id].tags`):
  метка → ярость (предмет) → крит → (реакции — волна 2) → броня элиты «Броня» (−50% от `proj`) → hp → поджог.
  Урон считается по оружию (`h.dmgBy`). Крит — событие `hit` с флагом.
- Новое оружие: Серп (летит к ближайшему на `range`, возвращается к владельцу, бьёт каждого врага по разу на каждом
  отрезке), Петарда (бросок в самую плотную группу среди 12 ближайших в 320 px, взрыв через `fuse`),
  Иней (волна от героя: урон + холод на `dur`, на 5 ур. заморозка), Капканы (ставятся на 30 px позади направления
  движения, если герой стоит — кольцом вокруг; срабатывают на первого врага: урон, корни, осколки по соседям).
  Заморозка и корни на боссов не действуют; замороженный враг не наносит контактного урона.
- Враги: Плевун держится в 260–320 px, раз в 2,6 с замах 0,6 с (бит 256) и сгусток прямо в текущую позицию цели
  (230 px/с, 8 урона, 2 с; попадание — по кругу `HOSTILE_R + PLAYER_RADIUS`, с учётом i-frames).
  Пузырь бежит к игроку, при касании — фитиль 0,5 с и взрыв r 60 (12 урона игрокам, 30 врагам); убитый — взрывается
  через 0,5 с на месте (событие `warn`).
- Элиты: с 4:00 раз в 45 с один из обычных врагов рядом с игроками становится элитой: hp ×8, радиус ×1,35, опыт ×3,
  аффикс из `ELITE_AFFIXES` (Быстрый, Кровопийца, Броня, Призрачный, Вспыльчивый). Награда — малый сундук
  (35% × (1 + удача)), иначе золотой кристалл. Сундук открывается касанием: предложение с повышенным шансом редкой карточки.
- Разрушаемые объекты: детерминированно по тайлу 400×400 (`breakableAt` в content.js, 25%: надгробие, бочка, фонарь),
  в снимок не идут; ломаются любым ударом оружия по площади, снарядом или касанием героя. Выпадение — `BREAK_DROPS`:
  Чаша росы, горсть кристаллов, Зов углей, Склянка ярости, Хлопушка, Песок времени, Перо. Предметы лежат 90 с.
- Упал (hp ≤ 0) → st=1. Живой союзник в `REVIVE_RADIUS` копит прогресс; `REVIVE_SECONDS` → поднят с `REVIVE_HP_FRACTION`.
  Все упали → `over` с win=false. Время ≥ `runLength` (режим комнаты) → `over` win=true.
- Босс на `BOSS_TIMES`: hp × число игроков; смерть — сундук: каждому живому игроку дополнительное предложение улучшения.
- Выход игрока посреди игры: его герой удаляется. Пустая комната удаляется. Хост ушёл — хост следующий.
- Статистика: kills и dmg по игроку (кто нанёс смертельный удар / сколько урона).
- Особенности героев — данные `HEROES[id].trait` (параметры) и `traitDesc` (строка для карточки);
  сервер читает их через `heroTrait(id)` и не проверяет имя героя. Отсутствующие поля нейтральны (`NO_TRAIT`):
  - `auraHeal` (Звонарь, 1) — другие живые игроки внутри его Ореола (`radius * areaMul` текущего уровня) лечатся на N hp/с;
  - `dmgTaken` (Кузнец, 0.8) — множитель получаемого урона; `taunt` (Кузнец, 250) — враг, у которого живой
    такой герой ближе этого расстояния, идёт к нему, а не к ближайшему игроку;
  - `chainBonus` (Заклинательница бурь, 1) — добавочные перескоки молнии Грозы;
  - `puddleSlow` (Алхимик, 0.35) — враги внутри его луж движутся медленнее на эту долю, пока внутри (+0.1 с).
  Особенность действует на соответствующее оружие героя, даже если оно взято позже, а не стартовое.
- Внешний вид: `HEROES[id].orbitSkin = 'hammer'` — Хоровод рисуется молотами (только клиент).

### Новые враги и волна 4 (v18)

- `SPECIALS` в content.js: Трубач (`sniper`) и Щитоносец (`shield`) приходят с доли забега `from` (как `PEAKS`),
  по одному раз в `every` ночных секунд, пока живых меньше `max[игроков − 1]` (с `late` — `lateMax`). Элитами не становятся,
  Хлопушка и звезда снимают им долю здоровья, как элитам.
- Трубач держится в 350–450 px, отходит при сближении; за `windup` с показывает полосу (`bline`) и выпускает веер из
  `fan` медленных шаров (`eorb`), целясь с упреждением `lead` с по движению цели.
- Щитоносец поворачивается к цели не быстрее `turn` рад/с; удар героя, стоящего в пределах `arc`° от направления щита,
  делится на 5 (`front`), сбоку и сзади — полный, поджог щит не замечает. Вблизи — рывок щитом с полосой, как у Рогача.
- События (`EVENTS`, `server/events.js`): первое на доле `EVENT_RULES.from`, дальше одно за раз через 90–120 с, не рядом
  с пиком и появлением босса и не в последние 45 с; общие для всей группы. Звезда, Золотая тень, Красный туман, Алтарь,
  Проклятый сундук (эпическая награда — `grantOffer(h, true, 2)` каждому, кто не падал за волну), Серия убийств (цель —
  темп убийств за последние 60 с × `pace`).
- `MODES[mode].dmgMul` (`modeDmgMul`, индекс = игроков − 1): урон врагов пары ×0,85 ночью и ×0,7 на обеде; соло и группы 3+ — ×1.
- Лог забега: `events: [{id, name, at, end, res, ...}]`, `specials: {sniper|shield: {spawned, killed, shots, blocked,
  first, dmgToPlayers, hit}}`; урон по игрокам — ключи `sniper:shot`, `shield`, `event:star` в `taken`.

## Клиент

- Экраны: меню (имя, список комнат с кнопкой «Войти», «Создать комнату», поле «Код комнаты»), лобби
  (код и кнопка «Скопировать ссылку» вида `<origin>/?room=CODE`, герои-карточки, игроки, «Готов», «Начать» у хоста),
  игра (canvas во весь экран), итоги (таблица, у хоста «Ещё раз», у всех «В меню»).
- Открытие по `?room=CODE` → сразу join.
- Движение: WASD/стрелки, на сенсорных экранах — виртуальный джойстик. Локальное предсказание своего героя
  (скорость из героя и пассива swift), отправка `pos` 15 Гц.
- Чужие игроки и враги — интерполяция между снимками с адаптивной задержкой. Часы отрисовки:
  `now − p90(приход − tm) − p90(интервал между tm) − 20 мс` по последним 40 снимкам (~4 с); к цели время отрисовки
  подтягивается плавно (скорость ±12%), прыжком — только при расхождении больше 0,5 с. Обычно задержка 150–250 мс.
  Если новый снимок опоздал, враги и чужие игроки до 0,2 с продолжают движение по скорости из двух последних снимков.
  Снимок с `tm` не больше предыдущего отбрасывается (кроме событий снарядов). Враг, сдвинувшийся между снимками
  больше чем на max(200, 400·Δtm) px, ставится сразу, без проезда через карту. Враг, которого не было в предыдущем снимке
  (вошёл в радиус отбора 1000 px), появляется на месте.
  Снаряды — интерполяция по id, новые появляются, пропавшие исчезают.
- Камера за своим героем; фон — тёмная земля с процедурной плиткой/травой (детерминированно по координате тайла).
- Всё рисуется кодом на canvas (без картинок): враги — разные силуэты/цвета из content.js, у героя — цвет игрока и имя.
- HUD: таймер, убийства, полоса опыта, уровень, здоровье, иконки оружия с уровнями, полоса здоровья босса,
  мини-список союзников со здоровьем, индикатор транспорта (WS/SSE) и пинг.
- Выбор улучшения — панель с 3 карточками поверх игры, клавиши 1/2/3 или клик; игра продолжается.
- Упавший союзник — силуэт и круг прогресса подъёма; стрелка на краю экрана к упавшим союзникам.
- Эффекты: цифры урона (криты — жёлтые, крупнее, с «!», свои ярче), вспышки смерти, молнии, дуга клинка,
  тряска экрана при получении урона и взрывах рядом.
- Состояния врагов по битам `e`: холод — голубой оттенок, заморозка — белая обводка с кристаллами, корни —
  коричневые штрихи у ног, горение — искры; элита — увеличенная фигура, золотой ореол, полоса здоровья
  и подпись аффикса; Пузырь с фитилём раздувается, мигает и показывает круг взрыва; Плевун на замахе раздувается и светится.
- Вражеские сгустки — зелёная капля с тенью и шлейфом; петарда летит дугой, в точке падения — пунктирный круг;
  капканы, предметы (у сундука — столб света) и разрушаемые объекты рисуются кодом.
- Панель улучшений: кнопки «Перебросить (N)» (клавиша R) и «Отказаться (+10 опыта)» (X); редкая карточка — золотая.
- Язык интерфейса — русский. Оформление — тёмная игровая тема.


## Список рантаймов

`GET /v1/infra/runtimes`

Возвращает список ID готовых рантаймов для передачи в [`POST /v1/infra/servers/:id/deploy`](./deploy.md) (параметр `runtime`). Рантайм — необязательный параметр: если нужный стек входит в список, передайте его ID и платформа установит пакеты автоматически. Если нет — на отдельной виртуальной машине деплой без `runtime` полностью рабочий: установите нужное ПО через `preStart` в теле запроса. У galaxy-приложения `runtime` обязателен, а `preStart` не применяется. На [`POST /v1/infra/servers`](/docs/infra/servers/create) рантайм без `source` НЕ принимается с 2026-04-25 — см. `RUNTIME_PARAM_REMOVED`. В одношаговом создании galaxy-приложения `runtime` передаётся вместе с `source`; `start` также обязателен, кроме `static`, где поле необязательно и игнорируется. Каждый рантайм — это набор системных пакетов (nodejs, python, nginx, базы данных), устанавливаемых на сервер. Оценочное время установки — 2–4 минуты для базовых, до 4+ минут для комбинаций с несколькими пакетами.

## Примеры

### curl — личный ключ

```bash
curl -H "X-Api-Key: YOUR_API_KEY" \
  https://vibecode.bitrix24.tech/v1/infra/runtimes
```

### curl — OAuth-приложение

```bash
curl -H "X-Api-Key: YOUR_APP_KEY" \
  -H "Authorization: Bearer USER_SESSION_TOKEN" \
  https://vibecode.bitrix24.tech/v1/infra/runtimes
```

### JavaScript — личный ключ

```javascript
const res = await fetch('https://vibecode.bitrix24.tech/v1/infra/runtimes', {
  headers: { 'X-Api-Key': 'YOUR_API_KEY' },
})
const { data: runtimes } = await res.json()
runtimes.forEach(r => console.log(`${r.id}: ${r.name} (${r.estimatedSetupTime}s)`))
```

### JavaScript — OAuth-приложение

```javascript
const res = await fetch('https://vibecode.bitrix24.tech/v1/infra/runtimes', {
  headers: {
    'X-Api-Key': 'YOUR_APP_KEY',
    'Authorization': 'Bearer USER_SESSION_TOKEN',
  },
})
```

## Поля ответа

| Поле | Тип | Описание |
|------|-----|----------|
| `success` | boolean | Всегда `true` при успехе |
| `data` | array | Массив рантаймов |
| `data[].id` | string | ID рантайма, передаётся как `runtime` при деплое (`POST /v1/infra/servers/:id/deploy`) |
| `data[].name` | string | Название для отображения пользователю |
| `data[].packages` | array\<string\> | Список пакетов, устанавливаемых на отдельной виртуальной машине (для справки) |
| `data[].estimatedSetupTime` | number | Оценочное время установки в секундах |
| `data[].supportedPlacements` | array\<string\> | Где рантайм доступен: `["standalone"]` — только отдельная виртуальная машина, `["standalone","galaxy"]` — ещё и галактика. Проверяйте это поле перед деплоем в галактику: рантайм с базой данных туда не ставится |
| `data[].deprecated` | boolean | `true` — линия языка больше не поддерживается: деплой работает, но новому приложению берите рантайм из `replacement` |
| `data[].replacement` | string \| null | ID рантайма, который заменяет устаревший, с тем же набором пакетов, например `node24-pg` вместо `node20-pg`. У поддерживаемого рантайма `null` |

## Пример ответа при ошибке

401 — не передан API-ключ:

```json
{
  "success": false,
  "error": {
    "code": "MISSING_API_KEY",
    "message": "API key required. Pass via X-Api-Key header."
  }
}
```

## Ошибки

| HTTP | Код | Описание |
|------|-----|----------|
| 401 | `MISSING_API_KEY` | Не передан заголовок `X-Api-Key` |
| 401 | `INVALID_API_KEY` | Ключ не опознан: такой строки на платформе нет |
| 429 | `RATE_LIMITED` | Превышен общий лимит запросов платформы |

Полный список общих ошибок API — [Ошибки](/docs/errors).

## Известные особенности

- **Для нового приложения на Node.js берите `node24` или его вариант.** Поддержка Node.js 20 закончилась 30.04.2026: исправления безопасности для неё больше не выходят. Рантаймы `node20*` остаются в списке для приложений, которые уже на них развёрнуты, и помечены `deprecated: true` с заменой в `replacement`. Переход на `node24` — это новый деплой с `runtime: "node24"`. Модули npm с кодом на C/C++ при этом собираются заново под Node.js 24, поэтому каталог `node_modules`, собранный под Node.js 20, в архив не кладите.
- **Деплой `node20*` на отдельную виртуальную машину может перезаписать настройки `apt` для NodeSource, заданные на машине вручную.** Когда команда `node` на машине не отвечает версией 20 — при первой установке рантайма или при возврате с `node24*` на `node20*`, — платформа ставит Node.js 20 установщиком репозитория NodeSource. Он заменяет ключ `/usr/share/keyrings/nodesource.gpg` и целиком перезаписывает файлы `/etc/apt/preferences.d/nodejs` и `/etc/apt/preferences.d/nsolid`: в них остаётся приоритет 600 для пакетов из `deb.nodesource.com`. Прежнее содержимое этих файлов платформа не сохраняет и не возвращает. Если установка через NodeSource не удалась и Node.js 20 поставлен из архива, файлы всё равно могут оказаться перезаписаны или удалены. Своё закрепление версии `nodejs` или свой ключ храните в копии и верните после деплоя. Деплои `node20*` эти файлы не трогают, пока команда `node` отвечает версией 20 и работает `npm`, а установщик `node24*` не трогает их вовсе.
- **Команда запуска зависит от рантайма — её указывают в поле `start` деплоя, кроме `static`.** Для `static` поле необязательно и игнорируется: платформа сама запускает nginx. Для остальных рантаймов на отдельной виртуальной машине используются такие команды: `node24*` и `node20*` — `node`, `python311*` — `python3.11`, `python312*` — `python`, `php83*` — `php8.3`. Команды `python3.11` и `python` работают и в галактике, поэтому такой `start` подходит обеим моделям размещения. На машине с `python311*` команды `python` нет, а `python3` остаётся системным интерпретатором Ubuntu 24.04 — это версия 3.12. Пакетный менеджер `pip` рантайм `python311*` привязывает к 3.11, поэтому `pip install` в поле `install` ставит зависимости в тот же интерпретатор, который запускает приложение.
- **У `python312*` пакеты приложения живут в отдельном окружении Python платформы.** На отдельной виртуальной машине Python 3.12 ставится из архива Ubuntu 24.04, а команды `python`, `pip` и `pip3` работают в окружении, которое платформа создаёт рядом с ним и сохраняет между деплоями. Поэтому `pip install -r requirements.txt` в поле `install` и `python app.py` в поле `start` видят одни и те же пакеты. Команды `python3` и `python3.12` остаются системным интерпретатором Ubuntu без пакетов приложения: `start` вида `python3 app.py` в галактике работает, а на отдельной машине приложение остановится на первом импорте пакета. Консольная команда пакета, например `uvicorn` или `gunicorn`, после `pip install` вызывается по имени, если команды с таким именем на машине ещё нет. Если машина раньше работала на `python311*`, одноимённая команда прежнего рантайма остаётся на месте — запускайте через модуль: `python -m uvicorn main:app`. Закреплённые версии `numpy` ниже 1.26 и `pandas` ниже 2.1 под Python 3.12 не собираются — поднимите их в `requirements.txt`.
- **Пакет `pm2` в списке рантайма — установленный на машине инструмент, а не способ запуска приложения.** Рантаймы `node24`, `node20` и их варианты ставят `pm2` вместе с Node.js, но поле `start` требует команду, которая остаётся на переднем плане и сама держит слушателя. Команда вида `pm2 start server.js --name app && pm2 save` запускает демон и завершается, а вместе с её завершением платформа останавливает и сервис приложения. Правило целиком, оба исхода такой команды и то, чем они различаются в результате деплоя, — [Полный деплой](./deploy.md), «Известные особенности».
- **Рантаймам `php83`, `php83-mysql` и вариантам с MySQL (`node24-mysql`, `node24-mysql-redis`, `node20-mysql`, `node20-mysql-redis`, `python311-mysql`, `python312-mysql`) нужен `"hardening": "off"`.** После установки MySQL пускает по локальному сокету только администратора, а PHP-FPM работает отдельным системным сервисом — под непривилегированной учётной записью приложение не подключится к базе. Платформа вернёт прежний режим сама, но попытка и её проверка работоспособности займут время на каждом деплое. Передайте `"hardening": "off"` в теле деплоя, чтобы её пропустить. Это не нужно приложениям, которые ходят в MySQL по TCP с паролем.
- **Комбинированные рантаймы работают только на отдельной виртуальной машине.** Суффиксы `-pg` / `-mysql` / `-redis` / `-rag` описывают шаблон отдельной машины: там рядом с языком действительно ставится PostgreSQL / MySQL / Redis. Galaxy-приложение — один контейнер языка на общем хосте, базы данных в нём не поднимаются и переменные подключения (`DATABASE_URL`, `PG*` и т.п.) не проставляются, поэтому деплой такого рантайма в галактику **отклоняется**: ответ `400` с кодом `GALAXY_RUNTIME_DB_UNSUPPORTED`, полем `details.suggestedRuntime` (языковая замена — например `node24` вместо `node24-pg`) и подсказкой. Какие рантаймы куда можно ставить, машинно видно в каталоге [GET /v1/infra/runtimes](./runtimes.md): у каждого элемента есть `supportedPlacements` — `["standalone"]` или `["standalone","galaxy"]`. Поля `name` и `packages` описывают установку на отдельной машине и не меняются. Приложению в галактике нужна база — возьмите языковой рантайм и передайте строку подключения к внешней (managed) БД через `env`, либо разверните приложение на отдельной виртуальной машине с исходным рантаймом.
- **Один и тот же ID рантайма может означать разные патч-версии в галактике и на отдельной виртуальной машине.** В галактике рантайм собирается из официального Docker-образа (`node:24-slim`, `node:20-slim`, `python:3.11-slim`, `python:3.12-slim`, `php:8.3-cli`, `nginx:alpine`) — версия следует тегу образа, и перед каждой сборкой платформа запрашивает свежую версию этого тега. На отдельной виртуальной машине major-версия закреплена и соответствует заявленной (Node.js 24, Node.js 20, Python 3.11, Python 3.12, PHP 8.3, PostgreSQL 16), патч-версия следует источнику установки: Node.js 24 каждый деплой обновляет до последней выпущенной версии линии 24 из официального архива с проверкой подписи релизной команды Node.js. Если критична точная версия — проверяйте её внутри приложения на целевой модели хоста, а не полагайтесь только на ID рантайма.
- **`estimatedSetupTime` — оценка, а не гарантия: при автоматизации закладывайте вдвое больше указанного.**
- **Если нужного стека нет в списке — используйте `preStart` на отдельной виртуальной машине.** Сервер — чистая Ubuntu 24.04 с рут-доступом. В поле `preStart` деплоя можно выполнить любые `apt-get install`, скачать бинари, настроить окружение. Результат сохраняется между деплоями (кроме директории `extractTo`, которую очищает `cleanDeploy: true`). Для разовых операций — [`POST /exec`](./exec.md).

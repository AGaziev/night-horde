# Ночная орда

Кооперативный онлайн-выживач до 8 игроков для Битрикс24 Vibecode.
Прод: https://app-0fdbcfb656d3.vibecode.bitrix24.tech (вход через Битрикс24).

## Где что
- `app/` — игра: сервер на Node 24 (`app/server/`), клиент (`app/public/`), общие данные (`app/public/shared/content.js`). Устройство — `app/DESIGN.md`.
- `pm/` — роадмап (`ROADMAP.md`), разборы живых забегов (`PLAYTESTS.md`), отчёты баланса (`balance-v*.md`), симулятор (`run-sim.mjs`).
- `changelog/` — тексты ченджлогов по версиям.
- `e2e/delta-prod.mjs` — проверка прода после выкладки.

## Запуск и тесты
```bash
cd app && npm ci
node server/server.js            # http://localhost:3000
for t in server/*-test.js; do node "$t"; done
```

[Server CI](.github/workflows/server-ci.yml) запускает все серверные тесты на Linux с Node.js 24 при обновлении PR в `main` и при push в `main`. В сводке указан проверенный SHA. Для PR это обычно результат пробного слияния, поэтому сводка также показывает SHA ветки и базы. В артефакте `server-test-logs` доступны логи тестов и `results.json`.

Тот же прогон с логами можно запустить из корня после `npm ci` в `app/` командой `node pm/run-tests.mjs /tmp/horde-server-tests`.

Нагрузочный тест локально проверяет среднее время CPU такта ниже 3 мс. На GitHub Actions тест сравнивает ту же метрику с периодом серверного такта (33,333 мс при 30 Гц) и показывает замер в сводке.

## Правила совместной работы
- Работаем через ветки и pull request в `main`; `main` = то, что выкладывается.
- Тег `vN` = версия, которая стоит или стояла на проде. `GAME_VERSION` в `content.js` поднимаем на каждую выкладку и не занимаем чужие номера.
- **Перед выкладкой** сверить, что на проде стоит последний тег из `main` (`GET /api/busy` → поле `v`), и что нет активных забегов и запланированных стартов (`playing: 0`, `scheduled: 0`). Выкладка мимо `main` затирает чужую работу — так 11.11 потерялись с прода v25–v26 (восстановлены веткой `dev2-v25-v26`).
- При выкладке обязательно `env.VIBE_APP_KEY` (ключ приложения) — иначе выключится сохранение прогресса. Ключи и токены в репозиторий не кладём (`.env` в `.gitignore`).
- Для приглашений при деплое передавай `HORDE_VIBE_SERVER_ID` и `HORDE_APP_ORIGIN` с адресом игры. Приложение читает именной список доступа сервера и отправляет уведомления с авторизацией хоста из шлюза.
- Проверки в браузере — без звука.
- Передавай текст `changelog/vN.txt` в поле `changelog` запроса деплоя Vibecode. После успешной выкладки проверь, что анонс с номером версии появился в чате приложения `chat4064111`. Если его там нет, отправь чейнджлог в этот чат и проверь сообщение по ID.

# Ночная орда

| Что настроить | Значение и источник |
| --- | --- |
| Базовая ветка | `origin/main`. Теги `vN` отмечают версии приложения на проде ([README](../../README.md)). |
| Чистая копия | Node.js 24. Из корня Git выполните `cd app && npm ci`. [Манифест](../../app/package.json), [lockfile](../../app/package-lock.json). |
| Быстрый прогон | Из `app/`: `node server/<feature>-test.js`. Для лобби и истории см. `server/lobby-invites-test.js` и `server/run-history-test.js`. |
| Полный прогон | Из `app/`: `set -e; for t in server/*-test.js; do node "$t"; done`. Перед прогоном сохранить SHA из `git rev-parse HEAD` и версию из `node --version`. Результат включает количество файлов, код выхода и вывод провалов. |
| Браузер | Запускайте Chrome с `--mute-audio`. Для проверки сети на проде используйте [e2e/delta-prod.mjs](../../e2e/delta-prod.mjs) и отдельный краткоживущий токен в защищённой временной папке. |
| Отдельный прогон | [Server CI](../../.github/workflows/server-ci.yml) запускает полный набор на Linux с Node.js 24 для PR в `main` и push в `main`. Укажите ссылку на запуск и проверенный SHA из сводки. Логи всех наборов доступны в артефакте `server-test-logs`. Aqua для проекта не используем. Продовый сервер выполняет только проверку выкладки. |
| Условие завершения | Актуальные SHA ревью и прогонов, полный набор тестов, критерии приёмки. Для выпуска отдельно проверить версию прода, отсутствие забегов и отсчётов, затем проверку сети из [README](../../README.md). Статус отдельного прогона отмечайте в карточке с указанием среды. |
| Изоляция | Отдельный worktree на задачу, уникальные `PORT` и `HORDE_RUNS_DIR`. Для локальной разработки без интеграции оставьте `VIBE_APP_KEY` пустым. В проверках доставки приглашений используйте тестовый ответ платформы или согласованного получателя. |
| Карточки и решения | Подкаталог `codex-project-team/` общего Git-каталога, который выдаёт `git rev-parse --path-format=absolute --git-common-dir`. Карточки в `tasks/`, решения в `decisions.md`. |
| Продуктовая роль | Профиль `team_product` и журнал решений. Постоянный чат подключается отдельно по [порядку работы](WORKFLOW.md). |

Отдельный прогон подтверждается ссылкой на запуск CI или логом с отдельного хоста. В журнале укажите исполнителя, среду, SHA и исход. Настройка игры, доступ и ключи описаны в README и документации платформы в корне проекта.
